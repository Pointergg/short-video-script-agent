# 方案与取舍

## 调用与职责

`providers.py` 接入 OpenAI 兼容 Chat Completions JSON 输出；每轮返回一个动作、参数和一句可审计依据。`agent.py` 把实际工具观察交回模型，模型自行决定检索改写、草稿修订、复查和结束。主循环不包含“超时就改稿”的业务分支；只负责参数校验、终态门禁和执行上限。离线 `MockProvider` 才使用预设逻辑，不能作为模型推理证据。

`tools.py` 提供四个本地函数：

1. `search_materials(query)`：本地关键词检索，返回完整资料与来源 ID；无结果与工具不可用使用不同返回值。
2. `write_script(script)`：保存结构化草稿，创建内容 SHA-256，清除旧检查。
3. `estimate_duration()`：根据当前草稿计算每镜配音单位、标点停顿和画面停留，返回逐镜时间线。
4. `check_rules()`：校验事实引用、标题、中性文案和画面白名单，返回逐镜结果。

模型只可调用注册的工具，不可执行任意代码。每次动作计入步数，包括错误和终止请求。默认 14 步，最大 50 步；单次网络调用超时 35 秒，不自动重试，不静默切 Mock。步数上限同时限制模型请求次数和工具调用次数。

## 事实守卫

素材中 `facts` 是管理员整理过的、允许发布的原子事实。事实片段必须与**已经检索到**的来源原文完全相等；不能把整篇不可信网页直接当作 facts。来源正文只作为数据进入模型上下文。

普通文案和画面也可能暗含事实，因此中性文案与画面采用品牌白名单。标题限于检索到的产品名称。拒绝用“neutral”标签绕过事实约束。严格模式会拒绝正确但未批准的同义改写，这是主动选取的保守边界，当前不是开放域自然语言事实判定器。

主机只有在当前草稿的事实规则通过、时长合格、两个检查的 draft_id 都对应最新草稿时才接受 `finish`。模型即使忽略工具失败、跳过校验或自行宣称完成，也无法绕过门禁。所有外部编辑都要重新提交 `write_script` 并复查；Markdown 是编辑稿，不自带永久“已审核”效力。

## 时长计算

每镜：`ceil_to_0.1(max(汉字或英文词数量 / 4 + 标点数 * 0.25 + 0.5, visual_seconds))`。分镜顺序串接，不重叠；起止时刻和总时长由工具计算，模型不能自报时长冒充通过。标题默认是画面文字，不计入配音；若需要朗读，必须显式加入片段。该估算不等于实际音频时长，语速参数尚未做语料校准。

## 技术取舍

Python 3.11+、标准库、原生 JSON 动作协议，不依赖 Agent 框架。小规模合成资料使用可解释关键词检索，避免向量数据库配置负担。JSON/Markdown 便于编辑和逐条核验。固定模型温度 0.2 不保证完全可重复，因此真实运行保留原始动作及实际工具结果，复现指工程行为可再运行而非承诺文本逐字相同。

当前限制：没有联网资料真实性核验、语义去重、自由文本事实蕴含模型、平台实时规则、持久化会话续跑或真实配音。API 使用单次标准库请求；部分供应商不支持 JSON mode 时须调整 provider，不能假定所有“兼容”服务行为一致。
